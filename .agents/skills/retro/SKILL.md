ユーザーが振り返りを依頼した。目的は、次回以降のセッションで Claude が同じ作業を短時間で、同じ指摘なしに完了できるように、作業の環境を改善すること。

## 手順

1. 対象のセッションの一次資料を確認する。会話、このリポジトリの Issue、プルリクエスト、コミットの履歴を参照する。指定がない場合は、現在のセッションを対象にする。

2. 以下の分類で、改善の候補を抽出する。根拠は、セッションの中で実際に発生した出来事に限定する。

   | 分類 | 抽出する条件 | 保存する場所 |
   |---|---|---|
   | スキル | 同じ手順を 2 回以上実施した。または、今後も繰り返す手順がある | `.agents/skills/<名前>/SKILL.md` |
   | ルール | ユーザーが同じ指摘を 2 回以上した。または、Claude が推測を誤った決定がある | `AGENTS.md` に 1 行 |
   | 自動の確認 | 機械的に判定できる誤りを、ユーザーが発見した | スクリプト、または GitHub Actions |
   | 情報の配置 | 必要な情報の探索に時間を使用した | `AGENTS.md` に場所を 1 行 |
   | 削除 | 動作を変更していないルール、重複したルールがある | `AGENTS.md`、スキル |

3. 候補を、効果の大きい順に最大 5 件提示する。各候補に、根拠の出来事、分類、保存する場所、内容の案を記載する。候補がない分類は記載しない。

4. ユーザーが採用した候補だけを作成する。変更は作業用のブランチで実施し、プルリクエストを作成して停止する。

## スキルを作成する場合

- `description` に、スキルの内容と、使用する場面を 1 文で記載する。Claude はこの 1 文で、スキルを読み込むかを判断する。
- 本文には、手順と、完了の条件を記載する。経緯と理由は記載しない。
- Claude が既定で実施する内容は記載しない。

## ルールを作成する場合

- 1 行にする。禁止する内容だけでなく、実施する内容を記載する。
- 特定の作業だけに適用する内容は、ルールではなくスキルにする。
